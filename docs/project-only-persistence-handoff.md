## Query/index and operation-cost contract to implement and measure

- Workspace: one tenant metadata read plus current client membership when applicable; request-local verified corporate policy does not create/read individual staff memberships. No hierarchy/bootstrap scans, raw time, PII or notes.
- Staff project page: default/max 25 records plus one pagination sentinel; stable document-ID cursor, schema version scope. Fetch monthly summaries by deterministic keys in one bounded getAll, at most one period document per returned row. Count those reads explicitly; getAll is not free. Project detail/notes are fetched only on demand. Cached pages invalidate by identity/tenant/revision after material writes, not on cosmetic tab changes.
- Client queries apply published AND authorized project scope before returning data or counts; filtering an unscoped page after limit is insufficient. No global counts, raw-time endpoints, private detail lookups or cursor contents exposing hidden IDs. Use opaque tenant/actor/scope-bound cursors. Query strategy must prove no unpublished-record count/search inference before acceptance.
- Planned queries/indexes: projects(schemaVersion, document ID); projectViews(schemaVersion, published, document ID); allocationRevisions(sourceId equality, revision descending); audits(entityId equality, at descending); source pages use only verified scoped project mappings plus date/ID pagination. Specify exact composite definitions after implementing these queries and verify with emulator/query tests; no index is declared deployed. Existing projectPeriods key lookups need no new composite index. B must not introduce a company-wide time scan as a shortcut.
- Create: bounded transaction reads tenant/identity scope/idempotency; writes one private project, one unpublished view, one idempotency result, one audit and tenant revision. Identical retry/no-op saves perform zero material writes. Edit/publication reads only target and relevant scope/revision, writes only changed project/view plus audit/revision. Existing source/allocation histories never enter generic project writes.
- Allocation: read scoped source, head, bounded authorized project set and affected summary documents; append one revision/audit and atomically update head/month/lifetime deltas. Preserve the existing maximum 10 portions. A missing mapping, stale source version or insufficient seconds yields a conflict, never partial totals. Changed work date requires removing old-month contribution before adding new-month contribution. No live importer is part of B.
- Maintain metrics for documents read/written, request size, retries/latency and transaction contention. Current tenant-wide revision can be a contention limit; do not claim platform-scale throughput from emulator success. Fail bounded capacity explicitly.
