# QuickBooks Online Accounting preparation

User reports the Accounting app is connected. Company/realm, grants and live authorization remain independently unverified. No API call or OAuth request occurred. disabledAccounting throws before network access. This product is separate from QuickBooks Time.

Proposed server-only Accounting scope: com.intuit.quickbooks.accounting, which is broader than the metadata this platform needs. Request no Payments or OpenID profile scopes merely to read customers. Candidate reads: Customer relationships, Job/sub-customer metadata and available project references. Do not presume every QuickBooks Projects field has an Accounting endpoint or that real work-order hierarchy follows names. Verify actual entitlement/endpoint response schema in an owner-approved sandbox task. M2 TimeActivity is a synthetic Accounting fixture, not the final operational time source. Morris caps/plans are never imported from QBO.

OAuth callback design: exact owner-approved redirect URI, one-use hashed state with short TTL bound to verified initiating admin/session/tenant, reject replay/mismatch before code exchange. Callback and exchange stay on Canadian backend; no credentials in browser or database. No callback URL is registered here. Secret Manager regional versions hold client secret and returned tokens. A per-connection lease and version check serialize refresh; persist the newly returned refresh token before publishing success, retry boundedly if secret storage fails, and require reconnect on invalid_grant. Never print codes, tokens, state values or callback URLs containing query credentials.

Intuit documents 60-minute access tokens and a refresh inactivity window; its later policy adds a five-year maximum. Honor returned expiry fields rather than assuming refresh continues forever. Rotation and reconnect handling are distinct from application login.

Plan paginated baseline, stable product/company IDs and explicit mappings, then documented incremental change feeds with overlap/checkpoint/replay tests. CDC resource coverage, lookback/object limits and project entitlement remain staging verification gates. Bounded retry/backoff with jitter; honor Retry-After on 429; one controlled refresh on 401; stop on repeated 401/invalid_grant and alert without payloads. Do not retry permission/schema failures forever. Checkpoint only committed batches; no-op comparison causes zero writes. No write-back, polling schedule or worker is activated.

Sources: [Intuit OAuth setup](https://static.developer.intuit.com/output_html/qbo/docs/develop/authentication-and-authorization/oauth-2.0.html), [authorization FAQ](https://static.developer.intuit.com/output_html/qbo/docs/develop/authentication-and-authorization/faq.html), [official refresh-token policy update](https://medium.com/intuitdev/important-changes-to-refresh-token-policy-8443779d40db).

Rate budget proposal: one in-flight read per connection, initially at most one request/second and three retries with jitter, honoring Retry-After and a bounded job deadline. This conservative design is not an entitlement claim; confirm per-app/realm/monthly limits against the [current Intuit limit documentation](https://static.developer.intuit.com/output_html/qbo/docs/learn/limits-and-throttles.html) before any sandbox worker.
